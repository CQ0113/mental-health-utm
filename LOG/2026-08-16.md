## 4. Bug fixes on the login flow

- **Quick-login mis-routing** (reported: clicking Admin logged into the client portal): root cause was `setData()` immediately followed by `.post()` in `login.tsx` — React batches the state update, so `post()` fired with the *previous* click's stale data. Fixed by posting the role directly via `router.post(url, { role })`, no form-state indirection. Verified with a real headless-browser test (not just curl, which couldn't have caught this).
- **Removed** the "Client Portal / Admin Portal / Counsellor Portal" toggle links that sat under every page header — a pre-auth leftover that let anyone jump portals with no check.
- **Added real logout** to all three portal layouts (`psycare`, `admin`, `counsellor`) — previously the client layout only faked a toast message, and admin/counsellor had no logout control at all. Now all three call `POST /logout`. Verified end-to-end for all three roles.
- **Diagnosed severe per-request latency** (3.3–3.5s on every page load): caused by `SESSION_DRIVER=database`/`CACHE_STORE=database` round-tripping to Supabase in `ap-southeast-2` on every single request. Reverted those two to local `file` storage (kept `DB_CONNECTION=pgsql` — real data still lives in Supabase), which dropped `/login` to ~20ms. Added persistent PDO connections for the pgsql connection to cut remaining cold-connect cost.
- Discussed setting up a local Postgres dev loop (Docker + Supabase CLI) to eliminate the *remaining* residual per-request latency (Supabase still gets queried once per request for `$request->user()`); clarified that a local dev DB has no effect on what a later published/deployed app would use. Docker Desktop was started and `supabase init` ran, but the user asked to stop there and defer — scaffold was removed, nothing left running.
